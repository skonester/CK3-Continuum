The [ordered contract-group definitions](../../ck3-mod-base/base/game/common/subject_contracts/groups/subject_contract_groups.txt) also changed between 1.19.0.6 and 1.20.0.3:

- Feudal, clan, and Japanese feudal groups insert `kurultai_rights` before `title_revocation_rights`.
- The nomad group inserts `council_rights` before `kurultai_rights`.

Those insertions shift later obligation positions. This matters for existing valid groups as well as the 3,398 blank groups in Barbara's save. Reconstruct old obligation identities from the appropriate version's definitions, map them to target positions, and apply target defaults only to newly introduced obligations. Preserve each saved obligation's selected level. A repair that changes only the group name while retaining shifted numeric positions can assign the wrong rights.

## Opinions, accolades, and culture

- [Opinion documentation](../../ck3-mod-base/base/game/common/opinion_modifiers/_opinions.info) explains duration, decay, delay, growth, monthly change, stacking, and bounds. Read the actual modifier definition when translating a saved opinion's state. The supplied modern save establishes the flat `value`, `modify`, and optional `days` fields; the loader rejects the old nested `converging` field. Preserve effective values and timing while translating its contents.
- [Accolade type documentation](../../ck3-mod-base/base/game/common/accolade_types/_accolade_type.info) describes rank-specific liege, knight, army, and unit effects. [Defines](../../ck3-mod-base/base/game/common/defines/00_defines.txt) provide glory thresholds of 100, 300, 600, 1000, 1500, and 2100, and permit up to three types. The [GUI](../../ck3-mod-base/base/game/gui/window_accolade.gui) and attribute definitions establish a maximum of three levels per acquired type. The [1.19 release notes](../../ck3-mod-base/base/release-notes/1_19_0_0_2026-04-20.md) identify the primary/secondary and deactivation removals as earlier changes; Barbara's save still contains those legacy fields. v0.4.2 retains both attributes with an explicit allocation policy and keeps inactive IDs and existing knight assignments in owner lists. These decisions require engine validation and are not claims of identical bonuses or inactivity behavior.
- [Culture innovation documentation](../../ck3-mod-base/base/game/common/culture/innovations/_culture_innovations.info) describes spread and fascination separately. The target save uses `spread_marker`; the [defines](../../ck3-mod-base/base/game/common/defines/00_defines.txt) describe spread through cultural acceptance. Preserve innovation progress and fascination while reconciling the old exposure state.

## Confirmed compatibility data

- [Trait conversion lookup](../../ck3-mod-base/base/game/common/traits/trait_conversion.lookup) includes `scholar → erudite`, `eunuch → eunuch_1`, and `poet → lifestyle_poet`. Lookup-name changes and trait XP migration are separate concerns.
- [Title conversion lookup](../../ck3-mod-base/base/game/common/landed_titles/title_conversion.lookup) explicitly maps `d_knights_hospitaler → d_knights_hospitaller`.
- [Scholarship perks](../../ck3-mod-base/base/game/common/lifestyle_perks/00_learning_2_scholarship_tree_perks.txt) define `erudite_perk`. The campaign's old `scholar_perk` references require a scoped alias with collision checks.
- [Late-medieval innovations](../../ck3-mod-base/base/game/common/culture/innovations/00_late_medieval_innovations.txt) define `innovation_gunpowder`; compare its unlocks and historical definitions when replacing `innovation_bombard`, preserving research progress.
- [Holy-order units](../../ck3-mod-base/base/game/common/men_at_arms_types/00_holy_order_maa_types.txt) define `order_serjeants` and `order_knights`. Their distinct unit roles need consideration when migrating the removed `teutonic_knights` type.
- [BP2 on-actions](../../ck3-mod-base/base/game/common/on_action/bp2_on_actions.txt) explicitly mark `bp2_parent_guardian_hostage_taker_pulse` deprecated and state that its events are also in the regular yearly pulse.

Game definitions and scripts establish content identities and behavior. Reference saves, loader logs, and simulation establish the persisted schema and whether a migrated record works. Use the installed executable and preserved minidump for crash analysis; the base repository tracks binary assets as metadata placeholders. Keep conclusions supported by each source explicit in the [cleanup review](error-log-cleanup-1.20.md).

The portable app includes only the functional contract-group/obligation/level identifiers and default indices in [definitions.rs](../native/src/conversion/upgrade/definitions.rs), extracted from the pinned 1.16.1, 1.19.0.6, and 1.20.0.3 snapshots. It does not require the external base checkout at runtime. Obligation-level ordering is unchanged across those snapshots; group ordering and administrative group length are not. Unknown groups and unsupported layouts fail before publication, except for the explicitly reported malformed republic fallback.
